## Problems and how they were solved
- **`npm error ENOENT ... package.json`:** I ran `npm run api` from `GymLog/` instead of `GymLog/frontend/`. Solved with `cd frontend`.
- **The form was not on the page:** my `App.jsx` was still the old version (`CatalogExercitii`, local journal), because I had used `git stash` and my changes were put aside. `git stash pop` was blocked by the changed `App.jsx`; I saved a copy, ran `git restore frontend/src/App.jsx` and then `git stash pop`, and the changes came back.
- **Wrong muscle groups in the form:** the first version of `ExercitiuForm.jsx` had groups that are not in my data. Fixed after comparing with `db.json`.
- **`db.json` error:** the file ended after the last exercise, without the closing `]` and `}`, so it was not valid JSON and json-server could not read it. I added the two closing lines.
- **108 exercises instead of 110, ids starting at 3:** I had deleted two exercises from the page while testing. Ids do not have to be consecutive, but I restored the two objects at the start of the list.

## What I learned
- In a controlled form the state is the source of truth: `value` shows the state, `onChange` updates it. Without `onChange` the field is stuck.
- `e.preventDefault()` stops the page from reloading on submit.
- "Server first, then state": the list is updated with the object returned by the server, so the `id` is generated by json-server and not in the frontend.
- The form is cleared only after a successful save (after `await`), so the typed text is not lost when the server is down. A disabled button while sending prevents adding the same exercise twice.
- `handleAdd` does not catch the error, so it reaches the form; `handleToggle` and `handleDelete` catch it and show it above the list.
- `data-testid` and `tw.json` do not change how the page looks; they only let the automatic check find the elements.
- Ids from json-server are not reused after a delete, so they can have gaps, and that is fine.
